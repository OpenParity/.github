## What this is

OpenParity builds and maintains open-source products for teams — and holds each one to a
single published bar, *the Parity Standard*, so that the capabilities a serious deployment
actually needs are present in the open source itself rather than reserved for a paid tier.

The name says the goal: **parity**. Not a stripped-down community edition beside a real one —
one codebase, one feature set, one licence.

## The Parity Standard

This is the bar we hold our own projects to. Every repository published under this
organisation carries a `PARITY.md` stating exactly which of these it meets today, and which
it does not yet.

| | Commitment |
|---|---|
| **Identity** | OIDC and SAML single sign-on, plus SCIM user provisioning, in the core codebase |
| **Authorization** | Role-based access control with custom roles, not a fixed admin/member split |
| **Audit** | A complete, queryable, exportable audit log of security-relevant events |
| **Observability** | OpenTelemetry traces, metrics and structured logs — no proprietary agent |
| **Portability** | A documented full-data export, in formats you can read without our software |
| **Automation** | A public API and webhooks covering everything the interface can do |
| **Self-hosting** | A supported, documented deployment path you can run yourself |

Where a project does not yet meet a line, the gap is written down rather than glossed over.

## How we work

- **Permissive licences.** Apache-2.0 for code unless a repository states otherwise. No
  source-available or business-source licence is used for anything in this organisation.
- **Public by default.** Design notes, roadmaps and decision records live in the repositories.
- **Original work.** Our projects are built from scratch or from clearly attributed
  dependencies, with third-party licences recorded in each repository.
- **Independent.** OpenParity is an independent project, unaffiliated with and unendorsed by
  any other company or organisation.

## Status

This organisation is new and its first repositories are in active development. Nothing here
is published as production-ready yet; each project will state its own maturity level in its
README when it lands.

If you want to be told when the first release happens, watch this organisation.

## Contributing

Contributions are welcome once repositories are public. Each will carry a `CONTRIBUTING.md`
and a code of conduct. Contributors keep copyright in their contributions and licence them
inbound under the repository's own licence.

## Security

Please do not open public issues for security reports. Each repository will provide a
`SECURITY.md` with a private disclosure address and expected response times.
